# 0.7.0：减少流程阻力，不降低成品要求

[English](WORKFLOW-UX.en.md)

## 为什么修改

一次真实 Session 暴露了：长篇用户返修意见没被识别、`diagnosis/target_stage_id` 被当成缺参数、稿件已过期却反复退到制作阶段、相同封面被要求改字节、ASS 原文卡和口播字幕混在一起校验，以及已交付状态连只读诊断都难以进行。

该会话固定的是旧 0.4.0 SOP，不代表机器实际安装的是哪个版本。这里修的是当前 Host 的运行逻辑和新任务的生产指导，不把旧运行偷偷改成新的已验证实验。公开回归只使用匿名合成案例，不包含用户原文、完整 Session 或成片。

## 日常使用保持不变

备份实际状态文件，用原服务账号和相同 DSH_HOME 更新、重启 Profile：

```bash
dsh plugin --profile web add github:rffanlab/dsh-playbook#main --force
```

新会话直接给任务。无需每一步手工指挥，也没有新增逐阶段审批。旧运行保留固定方法；新阶段说明需新任务才能完整使用。旧未隔离任务可只读诊断已有候选，但不能借此获取新的归属证明或跳过验收。

## 1. 用户说退回，就进入原任务返修

直接用户消息中的长篇正式审核，以及“打回当前候选，按第 22 节做 v2”等明确指令，均可进入原 run 的修订链。不会因为审核超过 1600 字，或者其中举了一个“如果……”例子，就丢掉整条返修意见。读取入口有 64000 字符上限，持久化反馈最多 24000 字符，原用户消息仍是完整依据。

代码块、引用、假设性问题、要求分析/翻译日志等不作为用户验收授权；接受仍须明确表示“验收通过”等。自然语言判断不是完美分类器，含糊时保留 `/playbook revise`、`/playbook accept` 人工入口。

## 2. 参数容错与精确错误

`repair` 接受 `stage_id + note`，也接受无歧义的 `target_stage_id/target_stage/target` 与 `diagnosis/reason`。结果返回 `argumentCorrections`，工具日志记录真实输入与纠正；相互冲突的别名会报错，不猜测。漏了阶段或提交错阶段会返回当前状态、准确字段和结构示例，既不假报通过，也不强迫重做已成功工作。

默认 `status`、`submit`、`report` 返回精简结果，保留当前目标、Gate、失败原因、恢复目标、产物目录和近期回执，不重复输出完整任务书与全部历史。需要原始证据时使用 `detail="full"`；人工 `/playbook status json` 与系统报告导出仍保留完整数据。**减少工具响应重复，不删除、不挪动用户上下文。**

## 3. 错在哪个依赖，就退到那里

正式 Gate 仍必须失败后才能修正：

| 错误 | 自动恢复目标 |
|---|---|
| 完整口播或逐段文本与固定版本不符 | `script`，不是来回撞 `produce/qa` |
| 交付时发现文件与 QA 快照不同 | `qa`，不自动重做所有素材 |
| 口播字幕内容或时间错误 | 当前 QA 修字幕或轨道选择，不必重新 TTS/生图 |
| 清单路径、时长/封面绑定信息错误 | 当前阶段核对真实引用，不能伪造文件 |

恢复会失效受影响的证据，但不删除素材或执行渲染；同一 run 未变的真实音频/画面可以复用。每个修订中，同类错误在同一来源阶段最多自动恢复三次，所有正式提交仍计入原全局 64 次 Gate 预算。超预算报告失败，不循环、不篡改验收标准。权限、归属、跨 Run 复用等错误不靠此机制放行。

## 4. 字幕与原文卡不是同一条时间线

支持 SRT，也支持直接检查 ASS 中指定的口播样式，无需为检查器另造一份不参与成片的字幕文件。

```json
{
  "subtitles": {
    "path": "final/captions.ass",
    "format": "ass",
    "narrationStyles": ["Txt"]
  }
}
```

`Txt` 的实际文本仍须覆盖完整口播；标题、原文引句等其它样式可作为视觉叠层，不会被算成重复口播。遗漏台词、删词改数字、真实口播轨重叠/越界仍拒绝。普通展示标点允许规范化，数字小数点、负号、百分号等有意义记号保留。格式不是任意猜测；ASS 应有正确 Events Format，Text 列在末尾。

**音频时长决定视频收尾，但不决定每张卡片的停留时间。** 一段原文自然朗读八秒，原文卡可以只出现两三秒，剩余口播继续配对应画面。不为凑画面时长加速/循环配音，也不把每个镜头机械固定到同样长。

## 5. 去掉伪质量检查，复用真正有效的检查

视频修改但通用封面字节未变，不再直接失败。返回封面内容复核提示，检查实际标题、时长文字和承诺是否仍成立，不允许用“改一个像素”应付。封面文件可解码、与当前视频绑定及正式交付文件一致性仍检查；没有声称 OCR 已识别封面文案。

handoff 对同一 Run 已过 QA 的文件重新计算哈希。全部媒体字节和相关引用/时间表不变时复用已测结果，不重复解码全片。文件或时间表变化仍 `QA_STALE`；改写无关报告备注不强迫重做视频。旧快照缺少新摘要时执行一次完整检查，过大的缓存摘要也回退到完整检查。

## 6. 等待验收不等于禁止查看

`present`、文件阅读、看图、任务输出查询可在不突破原工具策略时使用。需要实际媒体测量时，Agent 可调用：

```json
{"action":"diagnose"}
```

只诊断已有系统记录的候选/检查过的视频路径，不接受任意文件或命令。通过相同 Agent 的原 DSH 工具链执行固定只读检查，保留权限、沙箱与取消信号；拒绝时无裸 Shell 回退。结果明确 `readOnly=true`、`notAGate=true`，不能因此改变阶段、修订、接受状态或返修预算。普通任意 Bash 和修改仍需合法返修状态。

测量能说明解码、时长、采样、低电平区间等事实，**不能独立判断语音重复播放或逐字念对**。无 ASR，不把工具被拒绝后的模型猜测写成测量结论。

## 7. 样片别变成全片精修

新视频模板明确：pilot 只做一个自然完整段，验证既有制作链、音频与版式即可，不要把整条视频做完仍滞留样片阶段。轻微装饰最多尝试一次，不反复修到完美，不以不存在的 ASR 为由无限 TTS。

每阶段累计 32 次已观测工具结果后，状态/提示给出非阻断提醒，要求检查是否偏离阶段目标。**这是提醒，不是硬耗时/工具预算，也不会取消已提交的生成任务。** 此改动不能保证所有模型都遵守，也不能把实际生成等待时间都归因于 SOP。

## 保留的底线与验证范围

独立 Run 目录、全零音频拒绝、真实完整台词覆盖、文件哈希、同 Run 返修链、项目 SOP 的 draft/approved 边界都保留。没有“跳过所有 Gate”“自动批准自己”或任意改时间/改模型身份的入口。

状态继续 v3，新增可选恢复计数。新内置模板为 0.7.0，媒体机器结果协议仍为 0.4.0（协议标识不代表插件版本）。测试包括状态/控制器回归、真实 FFmpeg/ASS/SRT 夹具和原隔离测试。没有远程接管 E5，没有重新运行 Qwen/MiniMax；测试通过不是实际作品质量或耗时改善的证明。
