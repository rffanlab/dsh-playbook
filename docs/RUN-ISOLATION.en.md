# 0.6.0: per-run artifact ownership and validation lineage

[中文](RUN-ISOLATION.md)

Version 0.5.0 scoped methods to projects and state to sessions, but media paths were checked against the entire session workspace. A prior manifest/output in that workspace could therefore be accepted. Source inspection establishes that gap; an externally reported identical hash does not establish whether a particular incident involved reuse, wrong paths or a mistaken upload.

## Operation

Back up the actual state file. Update main with the same service account/DSH_HOME and restart the original Profile:

```bash
dsh plugin --profile web add github:rffanlab/dsh-playbook#main --force
```

Start a fresh conversation with the original task. Media-validator production runs (including inherited project video SOPs) allocate `<session-cwd>/.dsh-runs/<engine-UUID>` with brief/work/evidence/artifacts/final directories and an ownership marker. Model route/start prepares the directory through the original guarded DSH bash pipeline. There is no raw Host mkdir fallback. A command-start without a live tool token leaves preparation to the Agent's `playbook(action="workspace")`.

Session cwd and project-method identity are unchanged. In-place coding/deployment tasks are not forced into video output directories. Controlled revision retains the same root and revision history; a model comparison needs a new run/session, not just a model switch.

Use status.isolation paths for all media output and production.json. write/edit destinations and explicit bash workdir must be in that root. Direct reads of sibling managed runs/recorded old finals are refused. Public tooling can still be addressed explicitly but must produce fresh outputs inside this root. Arbitrary third-party tools are not assumed to enforce file isolation.

## Validation

The worker receives engine-assigned ownership rather than model-authored run_id. Manifest, script, segment audio, pilot, final, cover, subtitles and title must resolve inside the current root. Parent traversal, symlinks, hardlinks, modified ownership markers and preserved pre-run mtime fail. A two-second mtime tolerance handles timestamp precision. Copying/touching can refresh timestamps; this is supplementary evidence, not proof of generation.

Final-video hashes are compared against other retained run/candidate outputs. Copying known identical bytes into a new directory is refused as unestablished independence. A second check at serialized commit time prevents concurrent duplicate candidates. Identical bytes can also result from deterministic generation, so the check does not accuse a model of plagiarism.

For a known legacy result absent from retained state, the user can register its digest in DSH chat:

```text
/playbook exclude-hash <64-character-SHA256> Prior comparison output
```

The exclusion is workspace-scoped and has no model-side removal interface. No whole-disk baseline scan occurs. Unknown/untracked files cannot magically be recognized, and retained archives are limited to 20 previous runs per session.

## Lineage and limits

report/export_report includes engine run/session IDs, assigned directory, Host-selected model route, revision, validation stage/time and measured file paths/hashes/sizes/mtime. `verifiedInStage` is not an inferred creation stage; `verifiedAt` is not birth time; `creationAttested=false` explicitly avoids claiming which model generated bytes. Model route changes within a run remain visible. A model-authored sidecar is not authority.

This is **artifact acceptance isolation, not an OS/process read sandbox**. An arbitrary shell command can still address absolute paths; run_code/third-party services are not made incapable of reading other files merely by a workdir guard. Strong read separation requires a Harness/OS sandbox exposing only this run and explicit public inputs. No system permission changes, silent containerization or context filtering occur.

Hashes do not detect re-encoding/semantic copying. Neither timestamps nor author labels prove original creation. No ASR or creative-quality guarantee is added.

State stays v3 with optional isolation/exclusion fields. Existing unisolated runs are not silently migrated, copied or relabelled; their media checks request a new deliberate run. Old retained hashes remain useful. Back up before upgrading or downgrading.

Tests use synthetic fixtures only: allocation, Host dispatch, path/owner checks, duplicate hashes including concurrency, reporting, real filesystem links and actual FFmpeg decoding. No private sessions/videos/digests are published. CI is not an E5/MiniMax/Flash end-to-end experiment or proof of the historical incident's cause.
