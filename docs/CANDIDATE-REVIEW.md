# 0.7.3：聊天退回与候选评审入口一致

[English](CANDIDATE-REVIEW.en.md)

## 本次确认的缺陷

0.7.2 的 `reviewFeedback` 能识别“打回当前候选”，但把“拒绝候选”“拒绝当前候选”返回为 null。原任务于是留在 awaiting_review；此时 repair 不能替用户否决，recover 也不应制造一场插件事故来解除评审状态。这是可复现的解析缺陷，不是用户缺少授权。

旧 Web bundle 在“设置 → 插件 → Playbook”内已有“原任务返修”按钮，不是聊天工具卡上的“拒绝候选”。不能让用户寻找一个被模型编造了名称或位置的必需按钮。新版本将该实际按钮标为“拒绝候选”，但它一直是可选入口。

本轮依据用户提供的文字以及仓库源码复现，没有拿到此次完整 Host Session，因此不能断言用户部署中没有其他问题。

## 用户直接说退回即可

```text
拒绝候选，仅替换指定镜头；已确认文稿、语速、时长及其余素材保持不变。
```

“打回当前候选”仍支持。插件只处理被接纳的直接用户消息，在当前 Run 写入审核意见、递增 revision、进入既有返修阶段，并在同一轮把成功回执交给 Agent。不要求再点 UI，不取消旧 Run，不新开流程，也不自动通过后续 QA。

关闭新任务自动接单（auto off）不再同时关闭已存在候选的用户评审。普通闲聊、引述、代码块、否定句、解释/翻译请求以及工具或插件注入的文字不能成为评审授权。自然语言识别仍是保守规则，不声称能理解所有口语；已有显式人类命令 `/playbook revise <意见>` 继续有效，另提供 `/playbook reject <意见>` 同义入口。

同一用户消息 ID 重投递不会再次消耗修订，也不会错误否决之后的新候选。状态写入失败不报“已经退回”，保留原任务并返回实际失败；同一事件仍可重试。全局预算和修订上限未放宽。

## 状态提供真实可用的入口

候选状态的 `reviewControl` 同时用于模型响应与 UI，包含当前候选 target、自然语言短句、已有人工命令和可选面板位置，明确 `uiRequired=false`。

模型在 awaiting_review 调用 repair 得到结构化 `USER_REVIEW_REQUIRED`，包含真实状态与入口；recover 返回 `await_direct_user_review`，不把它错当成应当无限重试的技术事故。模型侧没有 reject/accept/revise 动作，不能通过自报“用户说过”生成审核授权。如果用户已经说过而状态未登记，应报告真实状态/版本/错误，不要求清空或绕开 SOP。

## 可选面板

设置 → 插件 → Playbook：候选待验收时显示“拒绝候选”“验收通过”，并可填写返修意见。面板打开且可见时每三秒只读刷新状态，不需要刚好在候选交付后手动刷新才出现按钮。

点击使用 `/playbook review reject|accept <target>`；target 绑定查看时的 run/session/revision/epoch/候选哈希，服务器在同一状态事务内复核。会话已经切换、候选已替换、旧请求重复点击，均不能错操作另一轮候选。target 只是防误操作的身份绑定，不是授权口令或数字签名。

界面退回只登记状态，回聊天发“继续”即可；直接在聊天发退回及修改意见，能够在同一 Agent 轮次继续处理，因此日常不需要打开面板。

## 更新

用原服务账号、相同 DSH_HOME 更新后重启原 Profile：

```bash
dsh plugin --profile web add github:rffanlab/dsh-playbook#main --force
```

刷新网页后回原会话，不取消、不清状态、不重建项目。重新发送上面的退回意见即可。`runtimePluginVersion` 应为 0.7.3；固定的 `run.playbookVersion` 可以仍为旧版，运行补丁不偷偷改写 SOP 定义。

新增源码/完整 Host 接线回归覆盖实际短句、否定/引述/工具文本、auto off、事件去重、落盘失败、正确作用域、修订预算，以及 repair/recover 不伪造评审。

另有 React + jsdom 测试渲染真正 `lib/client.js`，从真实按钮点击、输入意见，经模拟远端命令传输进入实际 Host handler；验证同 Run 返修、过期候选拒绝、会话切换和接受。这里的 DOM 测试不是真实 E5 Web Profile，也不是浏览器引擎端到端或模型生产视频的测试。
