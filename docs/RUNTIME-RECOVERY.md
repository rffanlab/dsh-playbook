# 0.7.1：插件故障在原任务内恢复，不让用户清状态

[English](RUNTIME-RECOVERY.en.md)

这次修正的是运行适配错误，不改写已批准的项目方法，不移除任何 Gate。插件版本为 0.7.1；既有 0.4.0/0.7.0 SOP 快照可以保留，不需要为使用修复而重新选题、重建项目或反复批准方法。

## 清单路径只解析一次

在有隔离目录的媒体 Run 中，以下三种写法指向同一个文件：

```text
/实际工作目录/.dsh-runs/当前UUID/work/production.json
.dsh-runs/当前UUID/work/production.json
work/production.json
```

第一种是绝对路径，第二种明确相对于 Session 工作区，第三种相对于当前 Run 根目录。清单内的 script/audio/subtitles 等引用仍然相对于清单文件的目录。Host 把清单参数规范成绝对路径后再执行验证；Python 入口也识别当前 Run 的显式前缀。不会拼成 `本轮根目录/.dsh-runs/同一个UUID/...`，也不会到其他目录碰运气寻找同名文件。

跨 Run 前缀、越界路径和 `..` 仍然拒绝。路径记法纠正返回 `pathResolution`，并不改变或创建文件；文件真实存在、内容对应、解码、哈希与归属检查照常执行。

## 已经被这个 Bug 卡成 failed 的任务

新增 Agent 控制动作 `recover`。系统从自己的失败记录识别旧清单路径基准错误，使用当前 Run 归属执行固定、只读的规范稿检查。检查实际成功后，在**同一 run、同一 stage、同一 revision**恢复工作。恢复本身不是 Gate 通过；模型仍必须提交本阶段完整证据。

`repair`、`workspace`、`route`、`submit` 遇到符合条件的适配事故会先尝试这一恢复，不要求用户输入取消命令。`status` 只提示下一步 `recover`，不会通过查询暗中修改任务。模型正常收到“继续”后可自行调用。不会主动取消已发布的后台任务，也不自动删除文件、清空运行记录或重建方法。

保留原失败事件、审核意见、候选、阶段数、重试与全局提交预算。每个补丁/阶段/修订的事故恢复至多登记一次；真实内容不一致、权限拒绝、跨 Run 复用、全局预算耗尽等不会被当作插件错误放行。读回执失败、磁盘错误、取消信号以及并发改变都保留原状态。自动恢复只有已记录的有限故障类型，不是任意“解除限制”开关。

## 升级前的旧 Run 正在返修

独立实验和继续修同一个作品是两种情况。对于固定在旧版、没有 Run 隔离、**已经有机器记录的候选，且有真实用户退回事件**的任务，可以建立 `legacy-same-run` 兼容续修范围。

范围只从该 Run 已验收记录中的清单目录与文件路径建立；不从模型随意提供的目录推导。先通过原 Host 工具链重读实际清单、核对全文覆盖，再解除那个精确的“旧 Run 缺少新隔离目录”的适配阻塞。不会把旧文件复制成新实验，不补写新作者标签，不更换原任务 ID，不清空资料，也不自动通过后续 QA。

范围外文件、另一个受管理 Run 的产物、符号链接、硬链接以及已知跨 Run 成品仍被拒绝。旧兼容范围没有新建目录的时间/归属证明；报告明确 `independentRun=false`、`creationAttested=false`。这只是原作品续修，不应用作新模型独立对照实验。新建任务仍强制分配独立 Run；模型不能删除新 Run 的隔离字段后选择旧兼容模式。

取消过的 Run 不自动复活。对于用户已经取消后重建、又遭遇路径故障的任务，只恢复当前仍可修复的 Run，已取消的历史继续保存。

## 不让模型背诵读取调用 ID

`intake` 新增 `source_paths`，由插件解析为当前会话实际观测到的 read 回执，仍检查完整分页覆盖。例如：

```json
{"action":"intake","project_id":"culture","requirements":["保留指定原文和完整台词"],"source_paths":["任务书.md"]}
```

只能选择已经真实读取的文件；不会把“我读过”当证据。使用不存在的调用 ID 时，返回实际可用的路径/回执选项，让 Agent 修正参数，不要求用户清状态。源文档与执行脚本不是同一个概念：不要把刚读取的一小段辅助脚本误声明为完整任务书。全文要求没有被删除。

## 如何继续

升级前备份原状态文件。使用原服务账号、相同 DSH_HOME 更新并重启原 Profile：

```bash
dsh plugin --profile web add github:rffanlab/dsh-playbook#main --force
```

刷新浏览器，回到原会话让 Agent 继续。正常路径不需要 `/playbook cancel`、清空 state 或新开会话，也不需要先给 SOP 开一个“不检查清单”的后门。`recover` 是 Agent 工具动作，不是要求用户手输的额外审批。

状态仍为 v3；新增兼容续修与事故恢复记录。写入失败回滚内存状态。权限边界沿用 DSH，固定验证命令仍继承 Agent、parent/rootCallId 和取消信号；没有裸 Shell 或裸文件读写降级。它不是抵御同系统用户恶意进程的沙箱。

## 验证与限制

Node 覆盖路径记法、跨 Run 拒绝、精确故障识别、保留预算、权限失败、磁盘回滚、并发取消、源路径回执和继续执行。Python 在真实文件上检查三种路径、缺文件、错稿、旧范围与越界。集成冒烟使用模拟 Host 调度执行真实 Python，并检查从旧失败状态恢复后正常提交 Gate；不等于真实 E5/模型端到端试验。

没有新增 ASR，也没有把音频循环、听感或作品质量自动判为合格。对于非本补丁所识别的真实故障，仍返回具体证据；不能建议删除验证器、降低已确认的验收条件或直接到 SOP 外制作来伪装成功。
