# 0.9.2：先分清交付物，再接收真实澄清，停止启动前空转

[English](INTAKE-RECOVERY.en.md)

## 已复现的缺陷

0.9.1 能把“制作视频”识别为视频，却可能漏掉“执行视频的生成”这种语序。随后一句“语音合成用本人声音”被认成了整个任务的输出，导致用户明明要成片，intake 却固定成 audio。推荐与模型自填 task 可以显示视频，真正 route 仍按最初捕获的错误分类拒绝。

另一个缺口是：ask_user_question 的人类回答作为宿主工具结果返回，不会再次触发 direct-user pre-step。旧代码只处理新用户消息，没有把这个真实回答接回已准备的 intake。任务未开始，没有 Run，因此阶段重试/返修预算也不能阻止反复选流和被拒的排查命令。

这不同于候选退回后 Agent 没被唤醒。0.9.1 的原生 steer 返修机制保留；0.9.2 修的是启动之前的交付物与澄清链。

## 修复行为

明确要求生成完整视频时，后续配音服务、本人声音、素材、字幕等从属制作要求，不再自动把任务变成纯音频或复合交付。支持“执行视频的生成”“进行成片的制作”等语序。同一条请求明确另交一首歌曲、另开发一个服务，仍视为多种交付物。仅配音、仅封面、只写文档、接入媒体工具、代码修复及视频审核不升级成视频生产。

当前 Agent 通过原生 ask_user_question 得到有效人类答案后，匹配真实工具调用、问题 ID 和选中标签或 custom 内容，更新启动前分类。保留原任务正文、真实来源读取记录、项目身份和本次要求。模型 note/task、普通工具日志、未选中的选项说明，以及过期/取消的问答都不能充当新的用户要求。已经创建的 Run、固定 SOP、Gate、权限和预算不受此入口改写。

启动前补充普通聊天要求也保留已有读取记录；引用新文档则重新要求 intake，不拿旧准备结果代替新资料。升级或 Host 重启后，用户在还没有 Run 的原会话说“继续任务”，可以从原生 Session 的直接用户消息恢复原任务文本，不扫描其他会话、不自动唤醒历史工作。旧任务资料仍需按正常要求实际读取。

## 只终止重复错误，不把用户限制为三次修改

相同待接单任务连续返回三次 SOP_TASK_MISMATCH、仍没有创建 Run 时，返回实际分类、调用 ID 和失败次数。支持的宿主使用公开 ToolExecution.concludeTurn() 结束这轮无进展的工具循环，保留原任务和日志；不 cancel Agent、不清 inbox、不新建 Run、不删除 Gate、不放宽 Shell。

这个计数只统计启动前选流冲突，不是用户返修次数或正常制作预算。正确的后续选流仍正常执行；真实用户补充可开始新的选择轮次。模型改 note、反复 status/reload 不能伪造用户澄清。若旧宿主没有 concludeTurn，仅能返回明确停止建议并披露 nativeTurnStop=false，不能声称强制停轮已生效。

这个止损处理不证明分类器永远正确；它的作用是让未覆盖的误分类成为一次可诊断的错误，而不是六十多次相同调用。它也不是全系统无限循环检测器。

## 使用

保留实际状态文件备份，使用原服务账号、DSH_HOME 更新后重启原 Profile：

```bash
dsh plugin --profile web add github:rffanlab/dsh-playbook#main --force
```

回原会话发“继续任务”即可。此次已复现故障尚未创建 Run，不需要取消、清状态、重新授权、改项目名或重建 SOP。Agent 应按已提供的完整任务书进入正确方法。运行版本看 runtimePluginVersion=0.9.2；已有任务仍保留方法快照版本。

若旧调用仍在反复空转，先用界面“停止”结束当轮模型调用再更新；停止调用不是取消/删除 Playbook 状态。补丁不会远程代替用户操作机器，也不会自动重播已取消的历史输入。

## 验证范围

匿名合成用例覆盖词序、制作约束、独立额外交付、真实 native-answer 关联、无效/伪造/迟到回执、已开始任务不可改写、保留 read 记录、原会话继续、完整 Host 接线及重复冲突止损。原始用户任务另做本地私有回放，不提交用户 Session、密钥或素材到仓库。

实际驱动测试使用同一固定上游 commit 的 Commands、AgentLoop、inbox、tools 和 LLM runtime；模型回复及人类答案提供者为脚本，不调用外部模型。上次 CI 的 published commands 与其他核心包属于不同预发布版本族，安装时报 peer 冲突，实际驱动测试没有运行。本版改为固定上游源码及其 lockfile，不用 --force/--legacy-peer-deps 混装宿主，不改变用户的运行依赖。

这些测试不等于 E5 实机验收、视频制作成功或所有自然语言都能正确分类。代码修复只处理已确认的入口故障，不能代替之后的实际内容与媒体验收。
