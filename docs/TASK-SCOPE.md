# 0.8.0：按交付物选流程，不按媒体关键词锁项目

[English](TASK-SCOPE.en.md)

## 本次缺陷

旧 `isVideoTask()` 在剔除少量句式后，只要整段任务或已读资料出现“视频、口播、B站”等词，就返回 true。`intake` 把这个结果保存成视频 hint，`authorize` 又把 hint 当作禁止选择非视频方法的硬规则。

因此，“把媒体 CLI 工具全局接入所有 Session”的软件任务，仅因为接入文档写着“输入支持音视频格式”，会被推荐 short-video-production；Agent 正确选择 dsh-plugin-development 或 task-intake 也会被拒绝。已有用户 Session 中还出现了为此要求用户重命名项目的情况。

源码与离线回放确认的是这个误分类链，不是所有其他权限错误。错误的 /root 路径、全局配置的实际写权限等，仍需按真实宿主环境处理，不能以本补丁为由绕过。

## 修复原则

**项目身份、文档主题与本次交付物是三个不同概念。**

- ProjectLibrary 仍隔离长期方法，不给项目贴一个永久的“必须出视频”标签。
- 路由建议、intake、方法派生与启动检查共用 `task-scope.js` 的交付物判断。
- 明确的用户请求先于附带手册、接口支持格式、代码示例和素材路径。只在用户将目标交给任务书且请求本身没有交付物时，才从已真实读取的任务书开头提取目标。
- 不对用户消息做删除或重排；这里的提取只用于分类，完整任务和来源仍传给执行流程。

| 用户目标 | 处理 |
|---|---|
| 同步/接入媒体工具、开发视频插件、修渲染代码 | 工程/配置流程，不需要口播、样片或 MP4 Gate |
| 只写视频文案、维护说明文档、生成字幕 | 文档任务；没有专用流程时用 task-intake |
| 只生成图片/封面，或配音/音频 | 不因“视频用的”这几个字变成视频生产 |
| 审核已有视频 | video-review，不强制从头制作一条视频 |
| 实际制作视频成片 | 保留对应文化/实验/短视频方法、独立 Run 和真实媒体验收 |
| 同时开发工具并制作示例视频 | 识别为 mixed，不能自动宣称一条流程覆盖全部；Agent 应说明当前处理范围 |

这不是把 20 个 SOP 改成新的审批系统，也没有给未知任务强行指定视频流程。规则不确定时保留 Agent 的选择和必要澄清，缺专用方法可用通用接单；不承诺语义分类在所有口语上都正确。

## 开始前可以纠正分类，不允许执行中降低标准

选择不匹配时返回 `SOP_TASK_MISMATCH`、`taskScope`、所选 base、建议 base 与 `nextAction=select_matching_sop`。含义是“Agent 应选对方法”，不是“用户没有授权”。不要求取消、清状态、换项目名或出一段不需要的视频。

旧的未开始任务 hint 在启动前重新计算；模型传入的 note/task/requirements 不能盖掉已经捕获的明确用户交付要求。已开始任务的 SOP、产物归属和预算保持固定，不能通过重新 intake 把失败的视频工作改成不检查媒体的工作。

项目中已确认的视频方法可以继续保存、复用，但不会管住同一项目里的插件开发或写文档。`sop_list` 增加 `matchesCurrentTask` 提示是否适配；不是删除不适配的方法。原先针对同一类已确认方法的改写/批准边界不变。

## 使用与兼容

先备份实际状态文件，用原账号、原 DSH_HOME 更新并重启原 Profile：

```bash
dsh plugin --profile web add github:rffanlab/dsh-playbook#main --force
```

本次误分类停在 intake、没有启动 Run 的原会话，可直接让 Agent 继续原来的工具接入工作。不用把 media-tools 改名成 host-integration，不用创建新 SOP，也不需要删视频方法。

重启会丢失旧版临时 intake 缓存；Agent 可根据原对话重新 intake/route，不能把已存在的全局配置猜成 /root 路径。实际加载版本以 `runtimePluginVersion=0.8.0` 为准；方法快照仍可能是 0.7.0，这个补丁没有重写方法定义。

状态仍为 v3，增加可选 `input.contract.taskScope` 诊断元数据。已在执行/等待评审/失败的 Run 不会被偷偷更换方法；当前补丁不是通用“解除全部限制”开关。真正的 Host 文件权限、外部操作审批、Gate 和媒体检查保持。

## 验证

单元覆盖中英文工具接入、文稿/字幕、配音、封面、视频审核、真正出片，以及附带 API 示例和文档主题干扰。完整 Host 接线回归包含：用户消息 → intake → 错误选择得到结构化提示 → 同项目改选工程流程 → 正常进入 contract/design/implement，确认没有媒体目录分配或媒体验证器。

另验证同项目已有已确认视频方法不影响工程工作、过期 hint 在启动前纠正、真实视频请求不能用模型自报改成配置任务，以及运行中的方法保护仍有效。公开测试只含匿名合成契约，不包含用户 Session、真实私有路径或密钥。

用户原请求与原工具参数另做私有离线回放：旧版误推短视频并拒绝工程；新版进入工程流程，视频 validator 数量为 0。回放和 CI 不是远程操作 E5、全局工具已经安装或新模型效果提升的证明。
