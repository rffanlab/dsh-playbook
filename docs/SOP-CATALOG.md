# SOP 目录

[English](SOP-CATALOG.en.md)

共 19 条起始模板。每条都有具体阶段指令、证据要求和失败策略；通过 `/playbook inspect <id>` 阅读完整定义。不是所有行业的最优流程，也没有经过真实模型交付率验证。

| SOP | 阶段顺序 |
|---|---|
| `bug-fix` — Bug Fix | Reproduce the defect → Find root cause → Implement the smallest safe fix → Verify the fix → Review scope and risk |
| `feature-development` — 功能开发 | 确认需求与验收 → 检查现有架构并设计 → 实现最小完整变更 → 验证原需求、边界与回归 → 交付产物与限制 |
| `plugin-development` — 通用插件开发 | 确认宿主与插件契约 → 定义边界与生命周期 → 实现插件与文档 → 验证原需求、边界与回归 → 在宿主中验证加载与卸载 → 交付产物与限制 |
| `dsh-plugin-development` — DSH 插件开发 | 核实 DSH 版本和接口 → 设计插件边界与状态 → 实现 DSH 插件 → 检查打包与入口 → 隔离 Profile 启动与 Web 验收 → 交付产物与限制 |
| `code-review` — 代码审查 | 确定审查范围 → 逐项检查行为与风险 → 验证发现 → 按影响交付审查报告 |
| `release` — 版本发布准备 | 核实版本和变更 → 构建与测试 → 隔离安装与回滚验证 → 交付发布包 |
| `incident-response` — 故障恢复 | 明确故障范围 → 选择最小恢复措施 → 实施授权范围内恢复 → 定位根因与回归 → 交付产物与限制 |
| `linux-service-deploy` — Linux 服务部署 | 核实主机与部署边界 → 设计可回滚部署 → 安装并配置 → 验证服务可用性 → 交付产物与限制 |
| `model-deployment` — 本地模型部署 | 检查硬件、模型与目标 → 确定推理配置与回滚 → 安装与启动 → 实测能力与负载 → 交付产物与限制 |
| `short-video-production` — 短视频制作 | 明确受众与交付 → 设计选题与开头 → 核实文案与来源 → 制作视觉、音频与字幕 → 观看成片并验收 → 交付产物与限制 |
| `bilibili-video-production` — B 站视频制作 | 确定问题与观众收益 → 收集实验或教程证据 → 组织叙事和视觉 → 自动化制作成片 → 观看与交付前检查 → 交付产物与限制 |
| `video-review` — 视频审核 | 确认素材可访问 → 检查开头、节奏和技术质量 → 检查事实与承诺 → 给出可执行修改清单 |
| `wechat-article` — 公众号文章 | 确认读者与材料 → 设计标题和结构 → 撰写文章 → 检查事实和阅读体验 → 交付 Markdown 与封面说明 |
| `music-production` — 原创音乐制作 | 确定音乐目标和权利 → 完成歌词与结构 → 设计编曲和生成参数 → 生成与整理音频 → 试听与技术检查 → 交付产物与限制 |
| `music-release` — 歌曲发行准备 | 核对作品和平台授权 → 校验音频、歌词与封面 → 整理发行元数据 → 交付上传包或授权上传结果 |
| `research-report` — 资料调研 | 界定研究问题 → 收集并记录来源 → 交叉核验并分析 → 核查关键结论 → 交付产物与限制 |
| `data-analysis` — 数据分析 | 确定问题与数据口径 → 检查数据质量 → 计算并解释 → 复算与核对 → 交付产物与限制 |
| `sop-authoring` — SOP 编写与验证 | 定义适用边界 → 设计阶段、产物与验收 → 生成可加载定义 → 验证加载、路由和失败分支 → 交付产物与限制 |
| `task-intake` — 未知任务接单 | 明确交付目标 → 核实工具与边界 → 制定有界计划 → 执行已明确的任务 → 按验收条件检查 → 交付产物与限制 |

## 怎么看验收要求

`inspect` 返回每个阶段的目标、具体指令、工具规则、证据字段、重试次数与下一阶段/失败目标。`status` 返回当前阶段和实际 Gate 失败原因。只提交真实存在的产物/观察，不要为了过关凑字数或编造执行结果。

大部分 Gate 允许提交两次，随后失败或按定义退回实现/制作阶段；整个任务另有 64 次总提交上限。内置 bug-fix 的 verify 还要求观测到 bash 工具成功，但这不等于 shell 退出码为 0 或测试已通过。

`release`、`music-release` 默认准备交付/上传包，不会默默授权公开发布、账号操作或签约。`task-intake` 明确属于未知任务兜底，不冒充专用专家流程。
