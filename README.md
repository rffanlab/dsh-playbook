# dsh-playbook

[English](README.en.md)

**按本次交付物选择工作方法，让 Agent 完成任务，而不是让所有任务适应同一条生产线。**

DeepSeek Harness 的通用 SOP 插件：方法目录、项目方法库、阶段证据、受控返修与执行报告。视频制作只是其中一种业务，不是引擎默认任务。

## 0.9.4：让小模型看到“该改哪里”，而不是猜验证器

针对 27B 在媒体 QA 中反复读取同一个 `production.json` 却无法理解 `A non-empty local path is required` 的真实卡死，验证器现在返回明确的 `MANIFEST_*` 错误码、JSON 字段路径、实测值和最小修复提示；常见的 `segmentTiming` 结构可直接兼容。失败 Gate 后连续三次完全相同的 read/grep/glob 会触发无进展保护，第四次不再继续空转。

目标不是替模型做内容判断，而是把 128B 通过读插件源码才能推出来的“接口契约”直接变成机器可执行的错误反馈。详见 [小模型恢复与诊断](docs/SMALL-MODEL-RECOVERY.md)。

## 0.9.3：没有合适 SOP 就正常干活

Playbook 现在是“**匹配到合适方法才接管**”，不是所有任务的强制入口。像卸载插件、执行一条明确维护命令这类没有专用 SOP 的任务，会直接按用户指令和 Harness 原有权限执行；不会因为出现“插件”“model”等词硬套开发/部署，也不会强制走 task-intake。`task-intake` 保留为用户明确需要规划/接单时的可选流程。

详见 [SOP 可选与直通规则](docs/OPTIONAL-SOP.md)。

## 0.9.2：纠正选流并接回真实用户澄清

“执行视频的生成＋本人声音配音”按完整视频处理，不因为配音约束变成纯音频。原生 ask_user_question 的实际人类回答接回启动前 intake；无 Run 的重复分类冲突有止损，不要求清状态或再次授权。原会话说“继续任务”即可继续，详见[启动前恢复](docs/INTAKE-RECOVERY.md)。

## 0.9.1：打回即投递返修任务

修复“退回命令成功、状态进了 diagnose，但 Agent 一直没开工”：命令/面板先保存意见，再调用原生 steer 唤醒原 Agent；返修中补意见留在同一修订，不报非法状态。普通聊天不重复启动。详见[返修唤醒与验证边界](docs/REVISION-WAKEUP.md)。

## 0.9.0：最终交付也绑定当前 Run

验收通过不代表模型最后找对了文件。现在从系统登记的候选生成固定交付副本，再通过原 DSH present 交付；不按文件名寻找 final.mp4。新视频任务的最终组装登记真实命令与前后输出，交付失败只重试交付。不是每个任务都绑定视频：该机制只作用于媒体验证流程。详见 [交付绑定、兼容与边界](docs/ARTIFACT-DELIVERY.md)。

## 0.8.0：修正交付物分类

“把媒体工具全局接入所有 Session”属于工程/配置，不因为接口说明包含视频格式、TTS 示例或封面路径，就要求生产 MP4。路由、intake 和启动检查现在共用交付物判断；项目身份与本次任务类型分开。完整原因、适用边界和回放口径见 [TASK-SCOPE](docs/TASK-SCOPE.md)。

| 请求 | 方法选择 |
|---|---|
| 开发视频插件、接入 CLI、修渲染代码 | 适用的开发/配置流程 |
| 写说明、只写视频文案、生成字幕 | 适用写作流程；没有专用流程时正常执行，不强制出片 |
| 只做配音、音频、图片或封面 | 对应任务，不升级成视频生产 |
| 审核已有成片 | 视频审核，不要求从头制作 |
| 制作一条完整视频 | 相应生产 SOP 与真实媒体检查 |

规则不确定时由当前 Agent 判断，缺关键任务条件才追问；没有适用专用流程时使用明确标注的通用接单。规则不是经过准确率验证的语义分类器，复合任务也不等于已实现多 SOP 自动并行编排。

## 更新与使用

先备份实际状态文件，用原服务账号、相同 DSH_HOME 和 Web Profile 更新：

```bash
dsh plugin --profile web add github:rffanlab/dsh-playbook#main --force
```

重启原服务并刷新网页，直接给任务。简单且明确的任务可自动选择；引用资料或需要项目方法时先读取、intake，再启动。不要求每次先写 JSON、手工选 SOP 或输入开始命令。

本次卡在 intake、没有启动 Run 的工具接入会话，可以继续原任务，不用改项目名、清状态或重建方法。实际运行版本看 `runtimePluginVersion=0.9.4`；已固定的方法快照可能仍显示旧版，不能据此判断补丁未加载。

## 引擎和业务规则分开

20 个基础流程覆盖开发、代码审查、发布准备、故障恢复、服务/模型部署、内容、音乐、调研和数据分析。只有选中的任务流程才规定阶段与证据；文档主题和公共工具支持格式不是本次任务的新要求。

项目库按 Host 工作目录＋project_id 隔离长期方法。同一项目可以同时维护工程和内容方法，不给项目贴永久“必须出片”标签。新定义可保存为 trial；改写已保护的方法要求进入 draft，由用户确认精确版本后 approved。具体参见 [项目 SOP](docs/PROJECT-SOPS.md)。

运行开始后固定方法与任务输入，不能为了过关自行删 Gate。技术问题在原 Run 受控返修；格式和已识别插件事故不应要求用户取消清空。用户明确退回不受“两次上限”约束；本轮自动尝试有界，历史总账保留。参见 [运行恢复](docs/RUNTIME-RECOVERY.md)、[用户返修与自动预算](docs/HUMAN-REVISION.md)。

模型填了证据不等于事实已被独立证明。软件命令回执证明实际调用和退出状态，不证明测试充分；产物检查证明被检查的性质，不代表用户满意或语义质量认证。

## 视频生产专用能力

仅采用媒体验证器的生产方法需要独立 `.dsh-runs/<UUID>`、规范稿/逐段文本、样片、音频/字幕和最终媒体检查。B 站实验与道家文化保留不同业务阶段。源码开发、文章和音频任务不因此获得视频检查义务。

视频候选可等待用户验收，直接聊天退回会关联原任务；可选面板不是强制入口。独立实验不能拿旧成片冒充新产物，同作品返修可复用未变素材。隔离是产物验收边界，不是完整 OS 沙箱或模型作者证明。见 [媒体返修](docs/MEDIA-REVISION.md)、[运行隔离](docs/RUN-ISOLATION.md)、[候选评审](docs/CANDIDATE-REVIEW.md)。

## 查看和控制

在 DSH 聊天框输入：

```text
/playbook status json
/playbook list
/playbook project
/playbook sops
/playbook report
/playbook auto off
```

这些是观察与人工控制入口，不是日常执行的前置步骤。`auto off` 关闭新任务自动接单，不取消活动任务。Web Playbook 面板提供方法查看/批准及适用候选的评审。

## 验证与边界

Node.js 20+，运行 `npm test`、`npm run check`、`npm run packcheck`。仅媒体检查额外需要 Python 3.9+、ffmpeg、ffprobe，使用 `npm run mediatest`。实际 DSH SDK 契约由 `npm run sdkcheck` 检查；CI 另跑 React/DOM 评审及模拟 Host 的真实 Python 测试。

状态保持 v3，单 Host 写入。方法、用户消息和状态历史不因分类修复而被删除；宿主的文件、外部操作和审批边界不变。测试不等于真实 E5 或模型端到端交付。没有新增 ASR、独立语义 Reviewer，不能保证所有任务选流正确或模型质量提升。
